# SSE 流式响应调试指南

本文用于排查 Ragent 问答过程中“连接成功但没有内容”“首包过慢”“输出中途停止”和“停止按钮无效”等问题。

## 关键入口

优先从以下代码建立调用链：

- `RAGChatController`：接收流式问答请求。
- `StreamChatPipeline`：组织会话、改写、检索、Prompt 和模型调用。
- `StreamChatEventHandler`：把模型事件转换为 SSE 事件。
- `StreamCallbackFactory`：创建流式回调。
- `StreamTaskManager`：登记和停止正在执行的任务。
- `SSEEventType`：定义前后端约定的事件类型。

## 排查顺序

1. 在浏览器 Network 中确认请求没有被普通 JSON 客户端提前消费。
2. 检查响应头是否为事件流，并确认代理没有缓存完整响应后再返回。
3. 记录请求 ID、会话 ID 和任务 ID，沿 `StreamChatPipeline` 日志向下追踪。
4. 区分“模型尚未返回首包”和“后端已返回但前端未解析事件”。
5. 中途断流时检查客户端取消、服务端异常、模型连接超时和任务主动停止。

## 首包延迟

首包耗时通常包含问题改写、意图识别、检索、Rerank、Prompt 拼装和模型首 token 时间。建议分别记录请求进入、检索结束、模型请求、第一条事件和完成事件的时间。

## 停止任务

停止操作需要使用与流式请求一致的任务标识。若停止无效，检查任务是否登记、前端是否携带正确标识、模型客户端是否支持取消，以及 finally 清理是否移除任务。

## 最小验证

本地联调时至少验证正常完成、用户主动停止、浏览器刷新断开、模型异常和后端超时五种路径，并确认每条路径都能释放任务资源。
