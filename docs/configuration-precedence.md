# 配置优先级与环境隔离说明

本文用于避免本地、测试和生产环境之间出现“配置文件看起来正确，但运行值不同”的问题。

## 配置来源

排查配置时按实际运行值追踪仓库默认配置、profile 配置、环境变量、JVM 或命令行参数、容器或部署平台注入值，以及前端构建时的 Vite 环境变量。后加载或优先级更高的来源可能覆盖仓库文件，不要只检查 `application.yaml`。

## 敏感信息

API Key、数据库密码和对象存储凭证不应提交到 Git。仓库只保留变量名、示例值和配置说明，真实值由本地环境或部署平台注入。

## 前后端差异

后端配置通常在应用启动时解析；Vite 变量通常在前端构建时写入产物。修改 `VITE_API_BASE_URL` 后需要重新启动或重新构建前端，不能期待浏览器运行时自动更新。

## 排查方法

1. 记录启动命令和激活 profile。
2. 检查进程实际环境变量。
3. 对关键非敏感配置输出启动摘要。
4. 确认容器、计划任务或 IDE 没有注入旧值。
5. 修改后完整重启相关进程。

发布前核对 context path、数据库、Redis、RocketMQ、对象存储、模型 endpoint、前端 API 地址和日志级别，并为配置变更准备明确回滚值。
