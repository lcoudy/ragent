# 检索评分调试指南

本文用于排查“能够检索到结果，但排序不合理”以及多通道结果合并后分数不可比较的问题。

## 保留原始信息

调试时为每条结果保留通道名称、原始分数、chunk ID、文档 ID、命中查询、去重状态、Rerank 分数和最终排名。不要只记录最终 topK。

## 多通道分数

向量相似度、关键词分数和意图定向检索分数可能不在同一量纲。合并前确认每个通道的分数方向和范围，避免把“越小越好”的距离直接与“越大越好”的相关度比较。

## 去重与 Rerank

去重通常发生在精排前。若多个通道命中同一 chunk，需要明确保留哪条结果以及是否合并来源。确认 Rerank 使用最终查询、改写查询还是原始问题，并检查传入文本没有被截断为空。

## 排查步骤

1. 固定查询和知识库版本。
2. 分别查看每个通道的原始结果。
3. 检查去重前后数量与保留规则。
4. 检查 Rerank 请求和返回顺序。
5. 比较最终 topK 与回答引用。
6. 调整策略后复用同一查询回归。

维护小规模固定问题集，记录期望文档、可接受文档和禁止出现的无关文档，评分策略变更时同时比较命中率、排序和延迟。
