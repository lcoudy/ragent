# 本地测试策略

本文帮助贡献者为小范围改动选择成本最低但有效的验证方式，避免每次都启动完整中间件环境。

## 测试分层

1. 纯单元测试：不依赖 Spring 容器和外部服务，优先使用。
2. 模块测试：只加载目标模块需要的组件。
3. 集成测试：验证数据库、Redis、RocketMQ、对象存储或向量库协作。
4. 端到端验证：覆盖前端、后端和真实依赖链路。

## 选择原则

工具类、分支判断和数据转换优先写纯单元测试。DAO、消息和文件存储改动需要集成测试。跨模块协议或页面流程再使用端到端验证。

## 常用命令

```powershell
./mvnw.cmd -pl bootstrap -Dtest=ClassName test
git diff --check
```

针对 `framework` 或 `infra-ai`，将 `-pl` 替换为对应模块。前端改动根据范围运行 lint、类型检查或 build。

## 依赖隔离与失败分类

纯单测中模拟网络、模型和中间件边界，不读取真实 API Key。测试失败后区分断言、编译、依赖下载、外部服务和环境配置问题，不要用跳过测试掩盖回归。

提交前记录执行过的命令和结果，确认工作区只包含目标改动，并使用与提交范围对应的最小检查。
