# 模型健康运维指南

本文说明如何观察 Chat、Embedding 和 Rerank 候选模型的健康状态，并在故障切换后确认系统已经恢复。

## 观察对象

模型健康不只是一个布尔值。至少关注候选模型标识、供应商、最近成功与失败时间、连续失败次数、是否参与路由、首包或请求耗时，以及最近错误类型。

## 故障切换

首选候选失败时，确认路由执行器是否继续尝试下一个健康候选。降级成功不代表故障消失，仍应对首选候选失败进行告警和记录。

## 恢复探测

恢复探测应使用低成本请求并限制频率，避免故障期间持续放大流量。探测成功后先恢复少量请求，再观察错误率和延迟。

## 异常分类

- 认证失败：检查 API Key、权限和 endpoint。
- 限流：降低并发或切换候选，避免无间隔重试。
- 网络超时：区分连接、读取和首包超时。
- 响应异常：保留脱敏后的响应摘要。
- 能力不匹配：确认 Chat、Embedding、Rerank 类型没有混用。

## 告警与恢复确认

为候选不可用、全部候选失败、连续降级、首包延迟突增和健康状态长期不恢复建立告警。恢复后确认路由重新选择首选候选、失败计数按设计清理、降级比例回落且结果质量正常。
