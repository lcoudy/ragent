# 知识库调度运维指南

本文面向知识库远程文档定时刷新场景，补充日常配置、监控和失败恢复建议。

## 核心组件

- `CronScheduleHelper`：计算下一次执行时间并检查最小间隔。
- `KnowledgeDocumentScheduleJob`：扫描到期计划。
- `ScheduleLockManager` 与 `ScheduleLockLease`：避免同一计划并发执行。
- `ScheduleRefreshProcessor`：下载、上传、分块并切换文档元数据。
- `ScheduleStateManager`：维护成功、失败和租约丢失状态。

## 配置与观测

创建计划前确认 Cron 能产生下一次执行时间，执行间隔符合限制，远程地址稳定可访问。每次执行至少关联计划 ID、文档 ID、锁 token、执行记录 ID 和 Trace ID，并观察扫描延迟、锁获取、下载、上传、分块和最终状态。

## 文件切换与租约

新文件上传并完成分块前，不应覆盖旧文件元数据。失败路径需要删除本次临时上传文件并保留可用旧版本。租约续期失败后应停止后续副作用，恢复运行中状态并清理临时资源。

## 恢复步骤

1. 根据执行记录确认失败阶段。
2. 检查远程文件是否仍可访问且内容确实变化。
3. 确认没有存活租约或重复任务。
4. 清理孤立临时文件。
5. 修复配置或依赖后重新触发。
6. 验证文档状态、分块记录和下次执行时间一致。
