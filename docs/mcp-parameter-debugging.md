# MCP 参数调试指南

本文用于排查 MCP 工具已经被发现，但模型调用时出现缺少参数、类型错误、非法 JSON 或工具执行失败的问题。

## 分层定位

MCP 调用可以拆成四层：工具发现、参数 Schema、模型参数生成和工具执行。先确定失败层级，再查看对应日志，避免只在执行端反复修改。

## 工具与 Schema

确认主服务连接的是预期 MCP endpoint，工具列表包含目标工具，同名工具有明确路由。Schema 应保持小而明确，必填项只保留真正不可缺少的字段，数字、布尔和数组使用正确类型，枚举值与执行端完全一致。

## 常见参数问题

- JSON 外包裹 Markdown code fence。
- 字段名与 Schema 不一致。
- 数字被生成为字符串。
- 缺失必填字段。
- 多余说明文字与 JSON 混在一起。

记录原始调用参数时必须对 token、密钥和隐私字段脱敏。

## 执行失败

参数绑定成功后，再检查工具内部异常、网络超时和下游依赖错误。返回结果应区分可重试错误、输入错误和永久失败。

## 最小测试集

每个新工具至少覆盖合法参数、空参数、缺少必填字段、类型不匹配、非法 JSON 和下游异常六类场景。
