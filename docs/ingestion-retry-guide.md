# 文档入库重试指南

本文用于设计和排查文档上传、解析、分块、向量化与消息消费过程中的重试行为。

## 识别失败阶段

重试前必须确认失败发生在文件存储、内容解析、分块、Embedding、向量写入、状态更新还是消息确认阶段。不同阶段的副作用不同，不能统一从头盲目重跑。

## 幂等标识

建议使用知识库 ID、文档 ID、版本或内容哈希组成稳定幂等键。消息重复投递时，消费者应识别已完成步骤，避免重复生成分块或重复写入向量。

## 可重试错误

网络抖动、临时限流和短暂中间件不可用通常可以退避重试。参数错误、文件格式不支持和权限失败通常需要先修复输入或配置。

## 临时资源与消息

每次执行产生的临时文件、上传对象和中间记录都要有归属标识。失败后只清理本次执行创建且尚未生效的资源。RocketMQ 消费重试必须配合业务幂等，达到最大次数后进入人工处理流程。

## 人工补偿

1. 确认没有同一文档的运行中任务。
2. 检查当前文档与分块状态。
3. 清理孤立临时资源。
4. 修复配置、数据或依赖。
5. 从安全阶段重新触发。
6. 验证分块数量、向量数量和文档状态一致。

不要通过无限重试掩盖永久错误，也不要在状态未知时删除旧版本数据。
