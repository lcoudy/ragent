# 发布验证矩阵

本文把常见改动类型映射到最低验证要求，供每日队列发布和正式版本发布复用。

| 改动类型 | 最低检查 | 冒烟场景 | 重点风险 |
|---|---|---|---|
| 文档 | `git diff --check` | 链接与命令可读 | 路径、端口和配置过期 |
| 工具类单测 | 目标测试类 | 正常与边界输入 | 类型、空值和异常分支 |
| 模型路由 | 模块测试 | 首选成功与候选降级 | 全部候选失败、超时 |
| 检索链路 | 单测加固定问题 | topK 与引用 | 去重、Rerank、分数方向 |
| 文档入库 | 模块或集成测试 | 上传到分块完成 | 重复消费、临时文件 |
| 调度刷新 | 调度单测 | 到期执行和失败恢复 | 重复执行、租约丢失 |
| 前端页面 | lint/typecheck/build | 加载、提交、错误提示 | API 解包、状态丢失 |
| 配置 | 启动检查 | 关键依赖连通 | 环境覆盖、密钥泄露 |

## 每日队列发布

每日脚本一次只发布一个队列 commit。发布前使用 `-DryRun` 确认下一条内容，再选择与矩阵对应的检查命令。文档类提交可使用当前任务配置的 `git show --check --pretty=format: HEAD`。

## 失败处理与证据

检查失败时不要推送半完成提交。保留失败输出，恢复干净工作区，在 `contribution-queue` 修复原任务后重新验证。发布后至少保留提交 hash、检查命令与结果、关键冒烟结果和回滚点。

## 周期复盘

每周检查一次队列剩余天数、计划任务最近结果和下一次执行时间。队列不足时提前补充真实任务，不使用空提交维持贡献记录。
